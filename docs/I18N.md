# AM — i18n & Localization Guide

## Overview

All user-facing text in AM is externalized into JSON string files under:

```
src/shared/i18n/locales/
  en.json   (English — source of truth)
  fr.json   (French)
  de.json   (German)
```

Keys use dot notation: `app.name`, `settings.language`, `omnibox.placeholder`,
`home.searchPlaceholder`.

## How it works

1. **Main process** loads the active locale at startup (`config.language`, default `en`)
2. **Renderer** requests the merged strings over IPC (`i18n:getStrings`) at boot — this works
   both unpacked and inside the packaged asar (no `fetch()` of local files)
3. Strings are applied to the DOM with:
   - `data-i18n` attributes → `textContent`
   - `data-i18n-placeholder` attributes → `placeholder`
   - `i18n.t('key')` in `app.js` for dynamic text
4. Changing the language in Settings reloads the locale over IPC and re-applies labels

## Adding a New Language (translator workflow)

1. **Copy the source file**: `src/shared/i18n/locales/en.json` → `es.json` (for Spanish).
2. **Translate every value**. Keep the keys unchanged — keys are the stable contract.
   Preserve interpolation placeholders such as `{{count}}` inside values.
3. **Validate coverage**:
   ```bash
   node scripts/check.js
   ```
   The checker reports any keys missing or extra relative to `en.json`.
4. **No code changes are required.** The i18n loader auto-discovers new locale files, and the
   Settings → Language selector offers them automatically.

## Guidelines

- Never hardcode user-facing strings in `app.js`, `index.html`, or `styles/global.css`
- Keep translated strings short — AM has constrained UI space
- RTL support is not yet implemented; when adding RTL locales, add `direction` CSS overrides
- UI code and labels must match the Via design language: pure black `#000`, `#5a83ff` accent,
  muted gray `#a0a0a0`, dim gray `#606060`
