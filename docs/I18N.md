# AM — i18n & Localization Guide

## Overview

All user-facing text in AM is externalized into JSON string files under:

```
src/shared/i18n/locales/
  en.json   (English — source of truth)
  fr.json   (French)
  de.json   (German)
```

Keys use dot notation: `app.name`, `settings.language`, `omnibox.placeholder`

## How it works

1. **Main process** loads the active locale via `setLocale(locale)` on startup
2. **Renderer** fetches the locale JSON at boot and applies it to DOM elements using:
   - `data-i18n` attributes -> textContent
   - `data-i18n-placeholder` attributes -> placeholder text
   - `i18n.t('key')` function calls in app.js
3. **Changing language** triggers a settings update, locale reload, and re-render

## Adding a New Language

### Step 1: Create the locale file

Copy `en.json` and translate every value. Save as `src/shared/i18n/locales/es.json` (for Spanish).

### Step 2: Verify key coverage

```bash
node scripts/check.js
```

It will report any missing or extra keys compared to `en.json`.

### Step 3: No code changes needed

The i18n loader automatically detects new locale files. The settings panel will offer the new language immediately.

## Translation Guidelines

- Keep JSON keys stable — do not rename after release
- Preserve interpolation variables like `{{count}}` in translated values
- Keep translated strings short — AM has constrained UI space
- RTL support: not yet implemented; add `direction` CSS overrides when adding RTL locales
